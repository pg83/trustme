# AGENTS.md

trustme — самостоятельный компилятор Rust (глубокий форк mrustc), написанный
на C++26. Компилятор находится в `bin/rustc/`, замена стандартной библиотеки
C++ — в `ext/libstd/` (там есть собственный CLAUDE.md), инструменты сборки и
кодогенерации — в `dev/`.

## Сборка и тестирование

Сборка выполняется внутри окружения ix:

```sh
env -u CC -u CXX /path/to/ix/ix run set/pg/libs -- bash -c \
  'export CC=cc CXX=c++ AR=llvm-ar SSL_CERT_FILE=/etc/ssl/cert.pem; ./build -j 20 -k <target>'
```

Цели: `rustc` (исполняемый файл компилятора), `ut` (лёгкие модульные тесты
компилятора), `unit` (gate: запуск UT, регрессионные тесты для отдельных
исправлений и проверки). В цикле разработки gate ограничивается целью `unit` —
никогда не запускайте полную группу `test`.

## Идеология: дивный новый мир

Заявленная цель этой кодовой базы — переписать всё, заменив идиомы `std::`
идиомами `stl::` (ext/libstd). Окружающий устаревший код — НЕ руководство по
стилю, а то, что подлежит замене. Никогда не оправдывайте конструкцию словами
«соседний код делает так же».

- Всё владение выражается через `stl::ObjPool` (`pool->make<T>(...)`). Объекты
  живут столько же, сколько их пул; по отдельности ничего не освобождается.
- Данные по возможности хранятся неизменяемыми, интернируются и устраняются
  дубликаты. Дескриптор — это сырой невладеющий указатель (или небольшой
  целочисленный идентификатор) на общие неизменяемые данные; равенство сводится
  к идентичности указателя или идентификатора.
- Сырые невладеющие указатели — это хорошо. Интрузивные односвязные списки
  узлов пула — это хорошо. Предпочитайте `stl::IntMap`/`stl::HashMap`/
  `stl::Vector`/`StringView` их аналогам из `std::`.
- `std::vector` — это плохо. `std::unique_ptr`/`std::shared_ptr` и владеющий
  сырой `new` полностью запрещены. Нельзя написать быстрый компилятор на
  `new XXX` и `unique_ptr`.
- Если пул недоступен там, где он нужен, либо передайте туда пул с подходящим
  временем жизни, либо создайте новый с подходящим временем жизни. Не помещайте
  временные данные в глобальный пул, но и не дробите пулы под каждое крошечное
  время жизни. Сотни и тысячи выделений в одном пуле — нормально; если их всего
  несколько, стоит ещё раз подумать, нужен ли отдельный пул.

Канонические образцы для копирования:

- Связывание компонентов: `bin/rustc/wire_board.h` — main строит граф в
  корневом пуле; компоненты хранят непрозрачные указатели и читают их в момент
  использования.
- Интернер с узлами пула: интернер `PathNode` в `bin/rustc/hir_path.cpp` —
  локальный для .cpp узел наследует структуру общих данных, содержит
  интрузивный `next` для цепочки соответствующего хеша, живёт в собственном
  `ObjPool` интернера и ищется через `stl::IntMap`; публичный тип дескриптора —
  единственный `const Data*`, а равенство определяется идентичностью указателей.
- Размеченные объединения: генерируются `dev/tu_gen.py` из спецификаций
  `bin/rustc/*.tu` — никогда не пишите варианты вручную.

## Храповик

`dev/std_ratchet.py` (запускается gate-целью `unit`) подсчитывает запрещённые
конструкции `std::` в каждом файле и сравнивает результат с
`dev/std_ratchet.baseline`. Счётчики могут только уменьшаться: любое увеличение
проваливает gate, а любое уменьшение автоматически переписывает baseline,
закрепляя улучшение. Никогда не увеличивайте baseline вручную.

Аварийный выход — только в случае крайней необходимости. Правила не абсолютны:
если запрещённая конструкция действительно неизбежна (форма FFI, неподконтрольный
вам интерфейс `std::`, подтверждённое измерениями исключение ради
производительности), добавьте в ту же или соседнюю строку комментарий
`// escape: <почему>`. Храповик пропустит эту строку, поэтому счётчик вырастет
только там, где необходимость явно зафиксирована. Причина обязательна; escape
без настоящего обоснования будет отклонён при ревью. Сначала используйте идиому
пула/интернирования: escape — последнее средство, а не альтернатива.

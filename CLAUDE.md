# CLAUDE.md

trustme: a standalone Rust compiler (hard fork of mrustc), C++26. The
compiler lives in `bin/rustc/`, the C++ standard-library replacement in
`ext/libstd/` (it has its own CLAUDE.md), build/codegen tooling in `dev/`.

## Ideology: the brave new world

The stated goal of this codebase is to rewrite everything from `std::`
idioms to `stl::` (ext/libstd) idioms. The surrounding legacy code is NOT
the style guide — it is the thing being replaced. Never justify a
construct by "the neighbouring code does it".

- All ownership is expressed through `stl::ObjPool` (`pool->make<T>(...)`).
  Objects live as long as their pool; nothing frees piecemeal.
- Data is stored immutable, interned and de-duplicated where possible.
  A handle is a raw non-owning pointer (or a small integer id) to shared
  immutable data; equality becomes pointer/id identity.
- Raw non-owning pointers are good. Intrusive singly-linked lists of pool
  nodes are good. `stl::IntMap`/`stl::HashMap`/`stl::Vector`/`StringView`
  over their `std::` counterparts.
- `std::vector` is bad. `std::unique_ptr`/`std::shared_ptr` and raw
  owning `new` are banned outright. You cannot write a fast compiler on
  `new XXX` and `unique_ptr`.
- If the pool is unreachable where you need it, either thread through a
  pool with the appropriate lifetime or create a new one with the
  appropriate lifetime. Do not put scratch data in a global pool, but do
  not fragment pools across every tiny lifetime either. Hundreds or
  thousands of allocations in one pool are fine; a mere handful should
  make you reconsider whether a separate pool is warranted.

Canonical patterns to copy:

- Component wiring: `bin/rustc/wire_board.h` — main builds the graph on
  the root pool; components hold opaque pointers, read at use time.
- Interner with pool nodes: the `PathNode` interner in
  `bin/rustc/hir_path.cpp` — a .cpp-local node inherits the shared data
  struct, carries the intrusive `next` of a per-hash chain, lives in the
  interner's own `ObjPool`, is looked up via `stl::IntMap`; the public
  handle type is a single `const Data*` and equality is pointer identity.
- Tagged unions: generated by `dev/tu_gen.py` from `bin/rustc/*.tu`
  specs — never hand-written variants.
